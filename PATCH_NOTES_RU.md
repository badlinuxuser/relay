# Relay 0.1.1 — patch notes

## Реализовано в этом патче

1. **Skills как пользовательская единица функциональности**
   - Обновлены инструкции `relay-builder`: модель сначала инвентаризирует установленные компоненты, затем выбирает один из вариантов — Skill без MCP, Skill с повторным использованием существующего MCP или новый MCP вместе с Skill.
   - Создание нового MCP описано как часть реализации пользовательского запроса на Skill, а не как отдельная задача, которую обязательно должен назвать пользователь.
   - Обновлены описания `propose_extension` и `create_skill`.
   - Убрана политика `OnceOnly` у `create_skill`, чтобы выбор «Always allow» работал согласованно с остальными инструментами создания.

2. **Пользовательские предупреждения**
   - В approval UI скрываются внутренние имена `mcp__...`, `create_mcp_server` и `create_skill`.
   - Для них используются понятные подписи «Relay capability» / «Always allow this capability».
   - Описание операции создания сервера стало ориентировано на результат для пользователя; диагностическая сводка о запускаемой программе и сетевых адресах сохранена.

3. **Прогресс создания Skill**
   - Сохранены анимированная строка активности, shimmer и таймер.
   - Убраны номера фаз и технические подписи фаз рядом со строкой прогресса.

4. **Синхронизация MCP с файловой системой**
   - MCP manager теперь наблюдает не только за `mcp.json` и trust-файлом, но и за entry point серверов, созданных Relay, в `connectors/<id>/server.py`.
   - Если такой entry point действительно удалён, компонент исключается из активного списка и останавливается.
   - Временные ошибки доступа к файлу не трактуются как удаление.
   - Внешние stdio-команды и удалённые MCP не требуют каталога `connectors/`.

5. **CLI MCP**
   - Добавлены `relay mcp info <id>` и `relay mcp validate [id]`.
   - `info` показывает конфигурацию, безопасные имена env/header полей, сведения об OAuth, наличие исходников Relay-сервера и доступное runtime-состояние/инструменты, если backend запущен.
   - `validate` проверяет конфигурацию и наличие entry point у серверов, созданных Relay.
   - `relay mcp remove` теперь требует подтверждение, поддерживает `--yes` и `--keep-files`, а при удалении исходников ограничен строго каталогом `connectors/<id>`.

6. **Документация и тесты**
   - Обновлены README, карта проекта и PROTOCOL.
   - Добавлены тесты для обнаружения удалённого исходника MCP и сохранения внешних команд.
   - Добавлен тест на сокрытие внутренних имён инструментов в approval UI.

## Проверка

- `gofmt` выполнен для всех изменённых Go-файлов.
- Точечные тесты новых сценариев MCP прошли:
  - `TestManagedServerDisappearsWhenItsEntryPointIsRemoved`
  - `TestExternalCommandIsNotTreatedAsManagedServer`
  - `TestManagerOmitsRelayServerWithMissingSource`
- Точечные тесты builder прошли:
  - `TestDescribeSummarisesWhatTheCodeCanDo`
  - `TestTheSixToolsAreDescribedAndGuarded`
- Полный `go test ./...` не удалось выполнить в исходной среде: проект требует Go 1.24.2, установлен Go 1.23.2, а загрузка toolchain и зависимостей заблокирована отсутствием сетевого доступа.
- Для сравнения были запущены тесты исходного архива с временным `go 1.23.0`: в исходной версии уже падают `TestConnectorWithOAuthBlockAsksBeforeTheCallAndGetsTheTokenFile`, `TestManagerListEnableAndPrompt` и `TestConnectorWithOAuthAsksForTheSignIn`. Эти падения не вызваны данным патчем. Точечные тесты изменённых частей проверены отдельно.

## Не входит в этот патч / требует отдельной проверки

- Не реализован MTProto для отправки сообщений **от личного Telegram-аккаунта**. В текущем Relay SDK нет Telethon/Pyrogram; бот через Telegram Bot API и личный аккаунт — разные способы интеграции. Патч улучшает процесс выбора/создания MCP, но не добавляет поддержку MTProto.
- Не исправлен отдельный timeout внешнего `browser-control`/Playwright при переходе на YouTube: это не связано с механизмом Skills/MCP, изменённым здесь.
- Не выполнен полноценный end-to-end прогон GUI и сценариев с реальными Telegram/внешними сервисами.
